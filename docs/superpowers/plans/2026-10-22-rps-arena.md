# RPS Arena Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein Comic-Browserspiel für Schere-Stein-Papier mit sechs Modi, Raum-Code-Multiplayer, Bot und optionaler Kamera-Steuerung, das per Helm auf Kubernetes läuft und bei jedem releasewürdigen Merge nach `main` automatisch released wird.

**Architecture:** npm-Workspaces-Monorepo. `packages/shared` enthält die reine Spiellogik und das Protokoll (kein I/O). `apps/server` ist ein Node-Server (Socket.IO, nur WebSocket-Transport, Redis als einzige Wahrheit für Räume, Timer als Zeitstempel in Redis). `apps/web` ist eine Svelte-5-SPA, die der Server ausliefert. Ein Image, ein Helm-Chart, ein Release-Workflow.

**Tech Stack:** TypeScript, Node 24, Socket.IO + `@socket.io/redis-adapter`, ioredis, zod, Svelte 5 + Vite, Vitest, Playwright, `@mediapipe/tasks-vision`, Docker (buildx, amd64/arm64), Helm, semantic-release, Renovate, GitHub Actions, GHCR.

**Spec:** `docs/superpowers/specs/2026-10-22-rps-arena-design.md`

## Global Constraints

- Matchformat Best of 3, 5 oder 7. Gleichstand-Runden zählen nicht und werden wiederholt.
- Der Server ist autoritativ: Die Wahl einer Seite wird bis zur gleichzeitigen Aufdeckung nie an andere Clients gesendet.
- Keine Accounts, keine Persistenz außer Redis mit TTL. Nickname + Comic-Avatar beim Beitritt.
- Raumzustand liegt vollständig in Redis. Kein Sticky-Session-Bedarf (Client nutzt nur `websocket`-Transport). Ein Pod-Neustart darf Räume nicht zerstören.
- 2v2: genau vier Plätze (`a0`,`a1`,`b0`,`b1`), Duelle `a0`↔`b0` und `a1`↔`b1`, kein Bot, nur Klassik-Gesten.
- Wheel-Sets: 7, 9 und 15 Gesten; jede Geste schlägt die nächsten (n−1)/2 im Uhrzeigersinn. Die 15er-Liste: Rock, Fire, Scissors, Snake, Human, Tree, Wolf, Sponge, Paper, Air, Water, Dragon, Devil, Lightning, Gun.
- Bluff-Ansage ist eine feste Emote-Auswahl (kein Freitext), unverbindlich, überspringbar.
- Kamera: MediaPipe läuft vollständig im Browser, es verlässt kein Videobild das Gerät; Bibliothek und Modell werden nur bei Aktivierung geladen; nur Klassik-Set; als „experimentell“ markiert.
- UI: Deutsch und Englisch, Standard folgt dem Browser, alle Texte über i18n-Schlüssel; `prefers-reduced-motion` respektieren; Layout auf Handybreite nutzbar; Design-Tokens als CSS-Variablen.
- Release: semantic-release bei jedem Push nach `main`. `feat` = Minor, `fix`/`perf` = Patch, Breaking = Major. Renovate-Updates als `fix(deps)` (Patch). `docs`, `ci`, `chore`, `test`, `refactor` erzeugen kein Release. Erstes Release `1.0.0`. semantic-release committet nichts nach `main`.
- Image: `ghcr.io/jaydee94/rps-arena:<version>`, multi-arch amd64/arm64. Chart als OCI-Artefakt in `ghcr.io/jaydee94/charts`, `version` und `appVersion` = Release-Version (im Repo steht ein Platzhalter).
- Chart: Ingress mit WebSocket-Unterstützung, Host und `ingressClassName` über Values, TLS/cert-manager optional, Redis im Chart abschaltbar (externe URL möglich), Probes, Limits, nicht-root, read-only Root-FS.
- Commits folgen Conventional Commits. Entwicklung auf Branch `feat/initial-game`.

## Review Focus

- Zweiter `pick` derselben Seite nach dem Sperren (oder Geste, die nicht im Set des Modus liegt) ändert nichts bzw. wird abgelehnt. → Task 3
- Der Gegner-Pick taucht weder im normalen State-Broadcast noch nach Reconnect/Rejoin vor der Aufdeckung auf. → Task 5
- Beitritt mit kleingeschriebenem oder von Leerzeichen umgebenem Code, unbekanntem Code, vollem Raum, leerem oder überlangem Nickname liefert eine klare Fehlermeldung statt eines Absturzes. → Task 4, Task 8
- Beide Spieler brechen ab oder der Raum bleibt leer: Raum verschwindet nach der TTL, und kein Timer läuft ewig. → Task 6, Task 8
- Kamera verweigert, kein Gerät vorhanden oder Gestenwechsel zwischen Frames: Klick-Steuerung bleibt voll funktionsfähig, und eine Wackel-Geste löst keine Wahl aus. → Task 13

  - Unentschiedene Runde ändert den Score nicht, `round` zählt weiter, und nach `advance` ist wieder `pick`.
  - **Review Focus:** Zweiter `pick` derselben Seite wirft `already_picked` und lässt `picks` unverändert; `pick(classic-state,'a0','fire')` wirft `invalid_gesture`; `pick` in Phase `reveal` wirft `wrong_phase`.

  - `timeoutPhase` in `pick`: Sitz ohne Wahl verliert sein Duell; fehlen beide Seiten eines Duells, ist es `draw`.

# RPS Arena Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A comic-style browser game for rock-paper-scissors with six modes, room-code multiplayer, a bot and optional camera control, which runs on Kubernetes via Helm and is released automatically on every release-worthy merge to `main`.

**Architecture:** npm workspaces monorepo. `packages/shared` contains the pure game logic and the protocol (no I/O). `apps/server` is a Node server (Socket.IO, WebSocket transport only, Redis as the single source of truth for rooms, timers as timestamps in Redis). `apps/web` is a Svelte 5 SPA served by the server. One image, one Helm chart, one release workflow.

**Tech Stack:** TypeScript, Node 24, Socket.IO + `@socket.io/redis-adapter`, ioredis, zod, Svelte 5 + Vite, Vitest, Playwright, `@mediapipe/tasks-vision`, Docker (buildx, amd64/arm64), Helm, semantic-release, Renovate, GitHub Actions, GHCR.

**Spec:** `docs/superpowers/specs/2026-10-22-rps-arena-design.md`

## Global Constraints

- Match format best of 3, 5 or 7. Tied rounds do not count and are replayed.
- The server is authoritative: one side's choice is never sent to other clients until the simultaneous reveal.
- No accounts, no persistence except Redis with TTL. Nickname + comic avatar on joining.
- Room state lives entirely in Redis. No need for sticky sessions (the client uses only the `websocket` transport). A pod restart must not destroy rooms.
- 2v2: exactly four seats (`a0`,`a1`,`b0`,`b1`), duels `a0`↔`b0` and `a1`↔`b1`, no bot, Classic gestures only.
- Wheel sets: 7, 9 and 15 gestures; each gesture beats the next (n−1)/2 clockwise. The 15-gesture list: Rock, Fire, Scissors, Snake, Human, Tree, Wolf, Sponge, Paper, Air, Water, Dragon, Devil, Lightning, Gun.
- The Bluff announcement is a fixed emote selection (no free text), non-binding, skippable.
- Camera: MediaPipe runs entirely in the browser, no video image leaves the device; library and model are loaded only on activation; Classic set only; marked as "experimental" (German UI copy: „experimentell“).
- UI: German and English, default follows the browser, all texts via i18n keys; respect `prefers-reduced-motion`; layout usable at phone width; design tokens as CSS variables.
- Release: semantic-release on every push to `main`. `feat` = minor, `fix`/`perf` = patch, breaking = major. Renovate updates as `fix(deps)` (patch). `docs`, `ci`, `chore`, `test`, `refactor` produce no release. First release `1.0.0`. semantic-release commits nothing to `main`.
- Image: `ghcr.io/jaydee94/rps-arena:<version>`, multi-arch amd64/arm64. Chart as an OCI artifact in `ghcr.io/jaydee94/charts`, `version` and `appVersion` = release version (the repo holds a placeholder).
- Chart: Ingress with WebSocket support, host and `ingressClassName` via values, TLS/cert-manager optional, Redis in the chart can be switched off (external URL possible), probes, limits, non-root, read-only root FS.
- Commits follow Conventional Commits. Development on branch `feat/initial-game`.

## Review Focus

- A second `pick` from the same side after locking (or a gesture that is not in the mode's set) changes nothing or is rejected. → Task 3
- The opponent's pick appears neither in the normal state broadcast nor after reconnect/rejoin before the reveal. → Task 5
- Joining with a lowercase code or one surrounded by whitespace, an unknown code, a full room, or an empty or overlong nickname yields a clear error message instead of a crash. → Task 4, Task 8
- Both players drop or the room stays empty: the room disappears after the TTL, and no timer runs forever. → Task 6, Task 8
- Camera denied, no device present, or gesture changes between frames: click control stays fully functional, and a jittery gesture does not trigger a choice. → Task 13

### Task 3: Match state machine

**Files:**
- Create: `packages/shared/src/match.ts`, `packages/shared/src/constants.ts`
- Test: `packages/shared/src/match.test.ts`

**Interfaces:**
- Consumes: `ModeId`, `gestureSetFor`, `duel` (Task 2).
- Produces:
  - `type SeatId = 'a0' | 'a1' | 'b0' | 'b1'`, `type Team = 'a' | 'b'`
  - `interface RoomConfig { mode: ModeId; bestOf: 3 | 5 | 7 }`
  - `interface RoundResult { picks: Partial<Record<SeatId,string>>; duels: { seats: [SeatId, SeatId]; result: 'a'|'b'|'draw' }[]; winner: Team | 'draw' }`
  - `interface MatchState { config: RoomConfig; phase: 'announce'|'pick'|'reveal'|'finished'; round: number; score: Record<Team, number>; announces: Partial<Record<SeatId, string|null>>; picks: Partial<Record<SeatId,string>>; lastRound: RoundResult|null; winner: Team|null }`
  - `class RuleError extends Error { code: 'wrong_phase'|'invalid_gesture'|'already_picked'|'unknown_seat'|'invalid_emote' }`
  - `activeSeats(mode: ModeId): SeatId[]` (2 seats, 4 for `team2v2`)
  - `createMatch(config): MatchState` (phase `announce` for `bluff`, otherwise `pick`)
  - `announce(s, seat, emote: string | null): MatchState`, `pick(s, seat, gesture): MatchState`, `advance(s): MatchState`, `timeoutPhase(s): MatchState`, `forfeitSeat(s, seat): MatchState`
  - `constants.ts`: `PICK_TIMEOUT_MS = 20_000`, `ANNOUNCE_TIMEOUT_MS = 8_000`, `REVEAL_MS = 4_000`, `RECONNECT_GRACE_MS = 30_000`, `ROOM_TTL_S = 1800` (**my decisions** per spec section 12), `BLUFF_EMOTES` = the gesture names of the Bluff set.
- All functions are pure and return a new state.

- [ ] **Step 1: Failing tests** in `match.test.ts`:
  - Best of 3: the first side with 2 round wins sets `winner` and `phase === 'finished'` after `advance`; best of 7 needs 4.
  - A tied round does not change the score, `round` keeps counting, and after `advance` the phase is `pick` again.
  - **Review Focus:** A second `pick` from the same side throws `already_picked` and leaves `picks` unchanged; `pick(classic-state,'a0','fire')` throws `invalid_gesture`; `pick` in phase `reveal` throws `wrong_phase`.
  - Only when all `activeSeats` have chosen does the phase switch to `reveal` and `lastRound` get set; before that `lastRound === null`.
  - `bluff`: starts in `announce`; only valid emotes or `null` are allowed; once everyone has announced/skipped, `pick` follows; `timeoutPhase` in `announce` jumps to `pick`.
  - `team2v2`: duels `a0↔b0`, `a1↔b1`; 2:0 duels → team wins the round; 1:1 → `'draw'`.
  - `timeoutPhase` in `pick`: a seat without a choice loses its duel; if both sides of a duel are missing, it is a `draw`.
  - `forfeitSeat` makes that seat's duel lose and evaluates the round as soon as the others have chosen.

Since tied rounds do not count and `bestOf` is odd, a series tie can never occur; the sudden-death rule is therefore covered by the replay rule (capture this in the test `'draw repeats until someone wins'`).
